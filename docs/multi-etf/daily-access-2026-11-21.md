## 日足原本で止まった箇所

JPX現行日報ページの公開スクリプトに記載された旧月別索引を2024年1月・3月・4月について各1回取得したところ、3件とも404。既存1475監査で使われた2024-01-15と2024-04-01の直リンクも現在は404。これを当時の監査内容が誤りだった証拠とは扱わず、旧URLが現在取得できない事実として記録した。

現行の[JPX株価情報（過去分）](https://www.jpx.co.jp/markets/statistics-equities/daily/03.html)には、ファイルの取得は手動を基本とし自動取得を控える旨が明記されている。過去原本の自動取得を停止し、収集スクリプトにも過去日報ファイルと旧自動索引への取得拒否を追加。掲載ファイルの転載禁止もあるため、原本のGit管理外保管を維持する。閲覧・保存が許される範囲は利用者が取得時に確認する。

この継続作業でのcollector記録は9リクエスト、HTTP 200は3件、HTTP 404は5件、CAエラーは1件。CAエラーだけを信頼済みCA設定で1回再取得した。Yahooへの再試行0回。損益計算0回。

## 手動取得が必要な資料

最優先は **JPXの2024年3月の株価情報原本（1475、2024-03-29を含むPDF）**。上記「株価情報（過去分）」から「2011年1月〜2024年12月」の案内を辿り、対象月を確認して手動保存する。旧日報の直リンクを推測して大量試行しない。

この1原本でまず1475の3月29日の高値・終値・出来高と、PDFの表の出来高単位を確認する。他のETFも同じ原本に載っていれば照合できるが、月次集計から日足を逆算しない。
続いて必要なのは、1月15日・4月1日の新しい取得導線、各ETFの分割市場切替日と当時単位、分配権利落ち日と支払日の証拠、監査用の連続OHLCV。原本がない状態で品質フラグを合格にしない。

## 原本の登録方法

`register_manual_market_source.py`を追加した。ユーザーが取得した元ファイルを変更せず、新規ディレクトリへ複製し、URL、実際の確認時刻、メモ、サイズ、SHAを保存。登録は出所管理に限り、価格検証合格とは扱わない。PDFの署名、URL形式、時刻、改変、上書きを検出する。PDFの本文抽出と目視照合は、実原本が届いてから行う。

```bash
PYTHONPATH=src .venv/bin/python scripts/register_manual_market_source.py \
  --input /path/to/manually-downloaded-202403.pdf \
  --source-url 'https://www.jpx.co.jp/markets/statistics-equities/daily/03.html' \
  --observed-at '実際に確認したタイムゾーン付き日時' \
  --directory data/raw/manual-202403-v1 \
  --note '手動取得。2024年3月、1475の3月29日を照合予定。実際の取得URLもここに記載'
```

上記日時やURLは実際の値に置換する。source-urlは可能ならPDF本体の実取得URLを指定する。PDFをHTMLのエラーページで代用しない。
