# 複数ETF研究の統合設計 v1

作成日2026-11-23。研究対象・禁止事項・固定戦略はユーザー指示、AGENTS、plan.md、plan-v2.mdを継承する。散在した要件と未設計部分を整理するための設計書で、実装済み・実データ評価可能という宣言ではない。

既存v1/v2、企業行動台帳試作、原本・試行・撤回記録は変更しない。以下の新しい会計/執行統合は将来の別版v3に実装する。実装前の設計登録と、実データ実験の事前登録は別。現時点の実データ許可はfalse、完全未使用期間なし、採用戦略なし。

## 2. 新版のデータ契約

既存input-schema.mdと別のschema_versionを持つ。旧形式から黙って変換しない。金額/比率は有限Decimalの文字列、口数は非負整数。浮動小数の残高丸めで買付余力を増やさない。金額は内部で端数保持、表示だけ丸める。手数料等に端数処理が必要なら出典付き規則を別フィールドで与える。不明な端数規則で実口座条件を認証しない。

共通の出典はsource_id、URL/原本path、retrieved_at、sha256、document_date、available_at、availability_basis（observed/documented_publication/historical_assumption/unconfirmed）を保持する。取得日時を当時の公表日時へ転記しない。過去利用仮定の結果を時点確認済み・完全未使用と呼ばない。

### 入力レコード

|レコード|必須項目・制約|
|---|---|
|Session|session_date、前後セッション、出典。指定期間とウォームアップの欠損/重複/市場差異を検査|
|Bar|symbol、session_date、raw OHLCV、source_id。NAVや将来調整済み値は不可|
|LotRule|symbol、effective_date、lot_size、available_at、source_id。初日前の単位と全変更履歴|
|SplitEvent|event_id、symbol、ratio_new_per_old、market_switch_date、legal_effective_date、split_record_date、available_at、source_id|
|EntitlementEvent|event_id、symbol、last_cum_session、ex_session、distribution_record_date、quote_unit_basis_id、source_id。日程根拠を直接/定義/暦候補に分類|
|AmountRevision|revision_id、event_id、supersedes_revision_id、quoted_amount、quoted_units、quote_unit_basis_id、status（estimate/final/correction）、available_at、source_id|
|CashEvidence|event_id、scheduled_payment_date、cash_available_at、status（schedule_only/observed/explicit_research_assumption）、amount、source_id。予定だけから利用可能日を作らない|
|ExecutionRule|symbol、適用日範囲、呼値、実際の値幅情報または検証の限界、取引規制、手数料条件、source_id、assumption_id|

quote_unit_basis_idは銘柄・基準日・分割前後を識別する。基準単位間の変換は、監査済みの分割イベントの連鎖から行う。市場口数と法的登録口数を同じ日付で置換しない。変換連鎖の欠落や矛盾は停止。未来の分割で過去の注文特徴量を正規化しない。

### 内部台帳

- Position：position_id、symbol、market_quantity、total_cost_basis、stop_price、entry_session、holding_sessions。
- Order：order_id、decision_at、target_session、quantity、lot、limit、cash_reserved、slot_reserved、fee_assumption、status、取消理由。
- EntitlementSnapshot：event_id、position_id、last_cum_session、quantity、unit_basis_id。ex日の売買前に保存し、売却後も削除しない。
- Receivable：event_id、position_id、entitled_units、estimate/final額、revision_id、valuation_status、paid_amount。買付余力には入れない。
- CashLot：amount、usable_from、origin（initial/sale/distribution）、source_id/assumption_id。注文への重複割当を禁止。
- Journal：journal_id、event_id、effective_session、recorded_at、revision_id、借方/貸方、旧新状態SHA。既存行を書き換えず訂正行を追加。

## 3. 二つの時刻と二つの評価

注文用ビューDはdecision_atまでにavailable_atが到来した情報のみで生成する。事後会計ビューRは、評価作成時点までに確認できた確定額や訂正に基づく。後日確定額によるRの訂正は、過去のD・注文・数量・日次損失判定を再生成しない。

権利落ち時には金額が未確定でも権利口数を保存できる。Dでは、当時利用可能な出典付き見込額があるときだけ債権評価に使用する。その後、確定額/訂正が公表された時点にDへ差額を反映する。Rは権利落ち日の帰属額を確定値で再表示できるが、必ずrestatedを付ける。DとRの差額・発生理由を日次で照合する。

見込額も不明なら「0円の分配金」を作らずunknownとする。Dの総資産が不明な場合、ポジション上限・日次損失を正しく計算できないため、当該比較期間全体をHALT_UNRESOLVED_VALUATIONにする。無取引継続や銘柄削除で比較を成立させない。停止までの台帳は診断用で、完了した戦略成績として出さない。Rだけ計算できても戦略の優位性を評価しない。

これは既存試作台帳の「既知額のみ」より広い設計。既存台帳をそのまま接続して対応済みとしない。historical_assumptionを用いる場合も対象情報・用途を事前登録し、後日の最終額を無断でDへ入れない。

## 4. 1セッションの順序

1. 監査・時点指定・状態SHA・直前セッションを検査。全イベントをIDで一意化。未確認条件による停止を約定失敗と混同しない。
2. 前日引けのポジションから権利口数を保存。前日作成注文と現金/枠の拘束を固定。前日までに判明した翌朝の企業行動・単位変更は注文作成時に除外し、朝に確定した変更は寄付前の失効として記録する。
3. 同日分配の債権を直前口数で認識。その後、市場切替日の分割を口数・損切り価格に適用。入力配列順に依存しない。
4. 利用可能時刻の根拠がある現金化を記帳。当日の入金・売却代金で既に凍結した注文を増額しない。
5. 前日終値で決まった売りを当日寄付で仮想執行。続いて凍結済み買いを固定優先順で判定。既存保有枠・注文枠の上限を事前に守り、売り見込み枠を先に利用しない。
6. 寄付が上限超・費用込み価格が上限超・数量が現金拘束超なら買いは不成立。取引停止・値幅/呼値・受付時刻・約定可能性が不明ならその実データ比較を停止。日足から部分約定量や日中のストップ約定を作らない。
7. 引けでDの資産を評価。直前引けとの損失比で翌営業日の新規買い停止と全決済を決定する。終値がstop以下またはSMA20以下、保有5営業日目終了も翌寄付売り。現物のない債権に保有日数制限を適用しない。
8. 最終日は事前予定の引け全決済。引けで実行できるという研究仮定と費用を保存し、実行可能性未確認を隠さない。債権は最終日後も残せるが、未確定評価があれば完了指標を出さない。

前日16時JSTを判断カットオフとする保守的研究仮定をv3で明示。寄付前に情報が追加されても買い数量は増やさない。現金化時刻が引け後なら、その次の判断時点まで新規注文原資にしない。実際の取引所/証券会社の受付再現には期間別資料が必要で、この時刻自体が実口座での発注可能性を証明するわけではない。

## 5. 資金拘束と会計恒等式

新規注文に割り当てる現金は、判断時点で利用可能なCashLot合計から既存拘束を控除する。注文ごとに数量×費用込み上限＋手数料を確保し、最大3枠も拘束。不成立/失効の資金解放で同じ寄付の別注文数量を再計算しない。

売却代金はv2同様、研究上は最短でも次セッションの注文作成から利用可能とし、実口座の受渡再現とは呼ばない。実データ評価時は実口座条件を確認するか、明示した研究仮定として結果に表示する。予定分配金は現金原資にしない。配当の入金予定しか分からない場合、完了会計と実行可能な再投資を同時に認証しない。

状態ごとに以下を照合し、不一致なら結果公開前に停止する。

- 利用可能現金−注文拘束 >= 0、総現金 >= 0、予約枠＋保有枠 <= 3（重複枠の表現を正規化）。
- 初期資金＋売却収入＋分配金入金−購入支出−手数料 = 総現金。スプレッド/スリッページは約定額へ含め、再度控除しない。
- 総資産 = 現金＋現物時価＋未収分配金＋確認済み未収端数代金（初版は端数を拒否）。拘束金は現金の内訳で、別資産として加算しない。
- 分割だけでは簿価総額を変えない。口数×ratio、stop/ratio。売却の単位不適合は停止し、売れない端数を売れたことにしない。
- 分配債権の入金は債権減少と現金増加を同額にする。原本のquote単位→権利単位の変換を一回だけ行う。

## 6. 原価・売却後の分配・税・端数

買い増しなしのため1銘柄1ポジション原価。買付代金と入口手数料を簿価総額とし、分割で総額不変。全決済の実現損益は売却手取り−簿価。分配額は別の所得欄に持ち、原価から減額しない。売却時点で未確定の分配は後日event_id/position_idで当該取引へ帰属させる。旧取引行を上書きせず訂正仕訳で関連付ける。

総損益・取引期待値・PF・勝率は、分配帰属と往復費用を確定してから算出。集計時に既に含めた分配をもう一度加算しない。R資産差分と取引損益合計＋未決済残高が整合することを必須とする。D時系列のDD/日次制限とR時系列の事後DDは別欄で示し、後日再表示したRだけで運用リスクを過小評価しない。

初版は既存どおり税引前。税率、NISA、損益通算、還付を推測して実装しない。「手数料控除後・税引前」を全結果に表示し、税引後優位性・手取り利益は未評価とする。税引後拡張は口座区分と適用時点の一次資料・別設計が必要。

分割/併合で端数が出るケースは初版では除外・停止。換金額/日付が分からない端数を0円、最終終値、架空の売値で精算しない。これは意図した未対応範囲で、将来実装しなければ今回の整数口数対象でも設計未完了になるという意味ではない。

## 7. 比較・統計・費用

既存主費用（フルスプレッド6bp/スリッページ2bp/片道手数料0円）は仮定を維持。適用コースや実測で確認できた値と混同しない。実データのscenario_labelに仮定・確認済み範囲を必須とし、資料不足を「実際の費用が検証済み」とするフラグで通さない。値幅/全量約定の不足がある場合も同様。

費用/リスク感度はconfig/swing.yamlの既存集合のみ、1要因ずつ。v3の比較回数上限450は旧計画の上限を継承するが、新実験登録前の実行予算は0。旧無効試行を削除して試行回数をリセットしない。合成の異常系テストは成績探索とは分けて記録する。

開発2024、検証2025、既視参考2026-01-05〜11-13を維持。全体/単一銘柄比較の各シナリオで除外候補と理由を損益確認前に固定し、結果を見て対象を絞らない。期間と最大3銘柄・5%上限を保有比較にも適用し、現金比率が高い比較であることを明示する。各期間に必要な前営業日と最低60本の判断履歴を別途確保し、不足を初期値/架空価格で埋めない。固定期間短縮は別実験。

指標は純損益、総/年率リターン、DD、シャープ、PF、勝率、平均利益/損失、期待値、取引数、保有期間、資金稼働率、コスト。算出不能はnullと理由。既存10営業日ブロック/1000回/固定seedのCI方法を継承し、30件未満で優位性確認としない。日次集計で同日銘柄間依存を保ち、分配訂正を帰属取引へ反映する。統計の前提・期間依存も報告する。

採用の必要条件は旧計画を維持するが、既視期間しかないため今回の結果だけで最終採用不可。利益未確認は未判定、費用後非正なら当該設定は不採用、未評価を不採用による損失実証と混同しない。恣意的スコア、利益が出るまでの再試行なし。

## 9. 全体の完了条件と停止理由

**設計整理完了**：R01〜R07、I1〜I6、データ契約、日次順序、未知額/税/端数/費用の扱いと受入条件が本書と対応表に存在すること。これは本書で整理した範囲の方針決定であり、全詳細の実装・市場条件の確認完了を意味しない。

**実装完了**：I1〜I6の正常/異常/統合テストが成功し、各要件に対応するテスト名・コードSHAを対応表に記録。注文・全状態・D/R差額の再現が一致し、旧エンジン結果を保持すること。

**実データ評価開始可能**：固定候補の採否/除外と期間を事前登録、必要日足/ウォームアップ/カレンダー/単位/企業行動/分配単位/情報時刻・利用仮定/費用・執行シナリオを照合し、新実験ID・比較回数・コード/入力/設定SHAを固定。全銘柄不可なら除外表を成果物とし損益を出さない。trueフラグだけで通さない。

**優位性の確認/採用可能**：品質・執行上の限界が評価目的に適合し、費用後期待値と不確実性、DD、資金効率、期間外再現の条件を満たすこと。現状は完全未使用期間がなく、この段階には未到達。将来のペーパーフォワード期間と条件は開始前に別途固定する。

**売買開始**：本作業ではローカルのペーパーフォワードまで。実売買開始の許可・計画・注文実装を本書から推定しない。AIは非AI結果を保存し品質/費用/再現性の条件が揃った後の独立比較計画まで。

残る市場資料：各銘柄211日分の日足に加えて必要ウォームアップ、権利日程・単位履歴・企業行動の網羅性、口数の基準、判断時点の見込額、入金利用可能時刻、期間別費用/執行条件。独立価格照合の1日という件数は参考で、全日の二重取得を新しい必須条件にしない。資料不足は未設計とは分けて記録する。
