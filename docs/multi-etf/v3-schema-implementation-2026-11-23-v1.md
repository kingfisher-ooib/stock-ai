## 入力契約

schema_versionは `stock-ai-swing-v3-synthetic-1`、syntheticは厳密なtrueのみ。ルートはJSONオブジェクト。旧形式・実データ・数値1によるtrueの代用・重複JSONキーは拒否。全モデルを凍結し、配列はtupleとして保持する。

|配列|主な内容|
|---|---|
|sources|出所ID、origin、locator、SHA-256、取得日時、資料日、利用可能日時・根拠|
|unit_bases|銘柄、単位ID、その市場単位が有効になる日|
|bars|銘柄別のraw OHLCV、日付、単位ID、出所、利用可能日時|
|lots|初期売買単位と適用日別の変更|
|splits|分割ID、新旧単位ID、比率、市場切替・正式基準・法的効力の日付|
|entitlements|権利ID、権利付き最終日、権利落ち日、基準日、引用単位、日程根拠|
|amount_revisions|見込/確定/訂正額、元版ID、引用口数・単位、利用可能日時|
|cash_evidence|支払予定日、現金利用可能時刻、予定/観測/研究仮定の区分、金額|
|execution_rules|期間別の合成呼値・費用仮定と仮定ID。実市場の規則表ではない|

金額・比率は有限で非負の十進数文字列、価格・分割比率・呼値は正。数量はboolを拒否する正整数。日付はISO日付、日時はタイムゾーン必須。負価格・NaN・数値型の価格を拒否する。

## 検査する整合性

- 全銘柄の日足が入力カレンダーと完全一致、重複なし。評価初日以前に最低60セッション、期間端点と初期売買単位が必要。OHLCの大小関係と正の出来高を確認。
- 日足の利用可能日時は保守的な16時JST以降。全レコードの利用可能時刻は出典の利用可能時刻以降、読取as_of以前。取得時刻もas_ofを越えない。
- 出所IDと単位IDは銘柄を含めて参照を検査。市場切替後の日足に旧単位を付けない。単位変更には一意な分割が必要で、新旧単位を連結する。
- 同日分割と分配金を別IDで保持できるが、まだ会計処理は行わない。同種同日の重複は拒否。権利付き最終日は権利落ち日の直前収録セッション。暦候補の権利日程は実行用入力として通さない。
- 金額改訂は一意で時刻が増加する一本の連鎖。孤立参照・循環・分岐・初期額の曖昧さ・確定から見込への降格・元版のない訂正を拒否。金額未判明なら改訂配列に0円を補わず、権利だけ保持できる。
- 予定区分の支払情報には現金利用可能日時を与えられない。観測区分では観測記録以前に現金が利用可能になっている必要がある。現金が権利より前になる矛盾はJST日付で判定。
- 各銘柄・評価セッションの合成執行規則がちょうど1件必要。抜け・重複を拒否する。

## 読み取りAPIと時点参照

`load_snapshot(raw: bytes, sha256=..., as_of=..., source_blobs={source_id: bytes})` を入口とする。原本バイト列は呼出側が明示して渡す。source.locatorは識別用で、ローダーが任意ファイルを開いたり、URLを取得したりはしない。ハッシュ一致は出典の真正性や抽出値の正しさを証明しない。source.originとavailability_basisも合成を必須とし、タグだけで真偽が保証されるとは主張しない。

`decision_view(snapshot, decision_at=...)` は利用可能時刻までのレコードを返す。後日確定額は保存されたまま過去ビューから除外される。既知の将来分割告知が返っても、その分割を過去の価格へ適用する関数ではない。最新の金額版選択、D/R債権評価、未知評価の停止、資金・注文計算はI2以降の責務。

構造検査済みでも `qualified_for_real_data` は常にfalse。JSON Schemaだけを通す、Pydanticモデルを直接構築する、品質フラグを書き足すといった方法を実行許可にしない。現状、戦略実行器はこのモデルに接続していない。
