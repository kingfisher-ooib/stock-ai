# 1475 Paper Forward Batch Import Design

## Intent

ペーパーフォワード検証の日次入力を省力化し、CSVまたはJSONファイルを1コマンドで取り込む。売買ルール、費用、Risk Engine、監査条件は変更しない。

## Approaches

1. Webからの完全自動取得：データ源の障害・後日修正・利用条件が増えるため不採用。
2. CSV/JSON一括取込：安価で出所ファイルを保存でき、既存監査ログも再利用できるため採用。
3. 1日1件の手入力：既に利用可能だが、転記作業が多いため補助経路として維持。

## Input

- CSVは`bar_date,open,high,low,close,volume`を必須列とする。
- JSONは1件のオブジェクトまたはオブジェクト配列を受け付ける。
- `source_observed_at_utc`は各行に指定するか、CLIの`--observed-at`で全行へ適用する。
- `provenance`がない場合、入力ファイル名とSHA-256を自動記録する。
- 行は日付順へ並べ替える。重複日付、既存最終日以前、16:00 JST前の観測、OHLCV不整合は拒否する。
- 同じファイルを同時刻に取得した複数行では、同一の観測時刻を許可する。

## Atomicity

全行をメモリ上で順番に検証・仮想決済する。1行でも失敗した場合は状態・監査ログを更新しない。全行成功後に、監査ログをまとめて書き、その後に状態を原子的置換する。2ファイル置換途中の停止は従来どおり次回読込で不一致停止する。

## Output

取り込んだ行数、最終日、各ルールの取引件数・期間損益・更新後資金、監査ログ末尾ハッシュを表示する。見送りは取引件数・勝ち件数へ含めない。

## Non-goals

Web取得、楽天証券連携、実注文、ルール変更、過去日足の上書き、ログ自動修復は行わない。
